# view 팔레트 조정 검토 기록

대상: dev, 기준 67dceb0. OMX1 A/B·OMX2 C/D별 사용자 정답 기반 조정 도구입니다.
자동 실기 구동·새 카메라 연결·FMS 수정은 수행하지 않았습니다.

## 1차: 구현 전 판정 정확성

| 발견 문제 | 반례 | 반영 결정 | 남은 위험 |
|---|---|---|---|
| 전체 팔레트 공통값으로 빈 격자의 잔여 차이를 구분하기 어려움 | 실제 빈 B의 격자 가림 9, D 15가 기존 빈 허용값보다 큼 | 품목별 parameters와 독립 empty_component_pixels 지원. 기존 기본값은 유지 | 실제 작은 물품과 잔여 격자 차이가 겹치면 임계값만으로 해결 불가 |
| 화면의 자동 판정을 정답으로 쓰면 오류를 학습할 수 있음 | PRESENT인데 UNKNOWN/EMPTY 후보가 나옴 | 사람이 고정된 촬영 사진에 EMPTY/PRESENT를 명시. 각 상태 3장 모두 일치해야 저장 | 사용자가 잘못 붙인 정답은 자동 검증 불가 |
| 한 사진만으로 허용값 확대 시 작은 물건 누락 | 밝은 물건이 빈 기준과 유사 | 각 상태 첫 2장으로 마지막 임계값만 제안, 나머지도 별도 비교. 거짓 EMPTY 횟수 표시 | 자료가 비슷하면 독립적인 실기 검증을 대체하지 못함 |

## 2차: 저장 직전 실행기 호환

| 발견 문제 | 반례 | 반영 결정 | 남은 위험 |
|---|---|---|---|
| diagnose 고정 파일을 다른 요청이 덮어씀 | 동시에 CLI와 view 촬영 | 기존 CLI 잠금 안에서 NPZ·JSON을 읽어 복사, frame_stamp 대조 | 같은 UID가 진단 파일을 임의 편집하는 경우는 운영 범위 밖 |
| view 설정과 실행기 설정이 다름 | 다른 YAML로 view 실행, 중간 설정 편집 | 절대 설정 경로·전체 팔레트 설정 해시·빈 기준 서명/픽셀 해시·세션 대조 | 실행기 재시작·설정 변경 시 촬영 자료를 다시 모아야 함 |
| 모델 실행 중 설정 변경이 모터에 영향을 줄 가능성 | 주문 중 촬영/저장 | 기존 워커의 홈·정지·관절/영상 신선도·주문 게이트 재사용. 저장 경로는 판정값 whitelist만 허용 | 이미 시작된 주문과 완전한 분산 트랜잭션을 새로 만들지는 않음. 모터/모델 쓰기 없음 |

## 3차: 검증 후 비용·유지보수

| 발견 문제 | 반례 | 반영 결정 | 남은 위험 |
|---|---|---|---|
| 클릭마다 무제한 사진·계산 누적 | 장시간 조정 | 품목당 12장·전체 24장, 별도 감사 NPZ 슬롯 24개. 자동 판정 재실행 폴링 없음 | 수동 비교 동안 Pi CPU를 잠시 사용함 |
| 반복 기준 경계 계산 | 정상 5초 검사 | grid_energy(reference) 중복 호출 재사용, 5개 합성 입력 전체 메타데이터 동등성 확인 | 실제 Pi P95·ACT 부하 영향은 현장 측정 필요 |
| 검증 실패를 저장 성공으로 보임 | 중복 영상, 디스크 오류, 보류·잘못된 PRESENT 판정 | 서버 측 재검사, 불일치 저장 거절, 원본 기준·재고 불변 시험 | 임계값으로 분리가 불가능하면 저장하지 않고 자료 제공 필요 |

검증: 변경 전 팔레트 시험 86개 통과. 전체 회귀 915개 통과(추가 반례 3개 추가 전).
최종 조정 시험 13개는 5회 반복 모두 통과. localhost HTTP·합성 RGB로 검증했으며 실제 카메라 정확도 시험은 아닙니다.
기존 모델·홈·보정·ROI·빈 기준·주문 파일 불변, 품목별 YAML 백업/즉시 적용, 품질 게이트·3회 연속 확정 유지 시험을 포함합니다.
실제 EMPTY/PRESENT 혼동행렬, Pi 5 처리 P95, 제어 지연 변화율은 아직 측정하지 않았습니다.
